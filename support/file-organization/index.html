File Naming and Project Organization

Consistent asset organization prevents broken images on web servers and keeps project files organized. This document provides guidelines for managing icon directories and naming rules.

Standardized Directory Structure

Separate your working files from final exports. Use the directory structure below: 

my-project/
├── raw/                 # Canvas saves and editable project files (.json, .sketch, .fig)
├── source/              # Uncompressed source vector/raster graphics (.svg, .png)
└── production/          # Optimized production assets scaled to targeted resolutions
    ├── 16x16/           # 16px raster assets
    ├── 32x32/           # 32px raster assets
    └── 512x512/         # 512px raster assets

This separation ensures websites and build tools do not load raw working files by mistake.

Machine-Readable Naming Rules

Follow strict naming rules to maintain compatibility across Mac, Linux, and Windows:

  • Character Set: Use lowercase alphanumeric characters (a-z, 0-9).
  • Separators: Use hyphens (-) to separate words. Do not use spaces, periods, or underscores (_) as word separators.
  • Suffix Modifiers: Append the specific scale/dimensions and theme variant as trailing segments.

Refer to this schema when constructing filenames:

Component Format Example
Prefix Type lowercase string icon, logo, badge
Descriptor kebab-case string home, user-profile
Dimensions [number]px 16px, 32px, 512px
Theme/State lowercase string light, dark, active

Valid Filename Example: icon-user-profile-32px-dark.png

Achieve Consistency with FileNamer

Manual renaming introduces human error. Use FileNamer to batch-process export outputs.

Configuration Steps

  1. Navigate to FileNamer.
  2. Load the exported PNG files into the drag-and-drop workspace zone.
  3. Set the naming pattern template in the schema configuration fields: 
    icon-{name}-{size}px-{theme}
  4. Define replacement parameters mapping your export layers to the template variables.
  5. Execute the batch processing engine to export the renamed files as a compressed archive (.zip) containing the structured assets.
